# RTX 4090 单卡验证记录（2026-09-21）

原始代码基线：`2e995a95b58fb91405c08a33614297af90496ab8`；本记录对应的单卡实现
已整理至提交 `7f4279e99e62544efad480ce55fca3683e1f6683`（分支
`codex/single-gpu-4090`）。本记录区分实际测量、短时微基准和未验证范围。
公开内容为工具、方法和结果摘要；下文的原始报告路径属于维护者私有测量目录，
不是仓库内的可下载附件。复现时需使用自己获授权的头像、音频和 API 凭据。

## 运行范围

- Linux、RTX 4090（24564 MiB），测试期间本系统只使用物理 GPU 1。
- CPU 为 Xeon Gold 6530，64 个逻辑 CPU；这是服务器上的消费级显卡验证，
  不是 Windows 家用整机性能保证，也未测得最低主机内存需求。
- Python 3.11.15、PyTorch 2.8.0+cu128、Pipecat 1.6.0。
- GPU：DyStream 动作生成、LIA 512×512 渲染、官方 VoxCPM2 BF16 流式声音克隆。
- CPU：ASR 和参考头像关键点。对话 LLM 仍使用原有远程 API，不是全离线系统。
- 保持实时入口原有的 1 步动作去噪、VoxCPM2 的 10 步生成；渲染 stride=2，
  因而目标为 25 Hz 动作时间轴、12.5 帧/秒新渲染画面，不宣称输出 25 FPS。
- 单卡模式启用 EMA 合并、零系数 CFG 分支裁剪，以及音频历史 8 秒上限/4 秒保留。
  仅最后一项改变远处音频上下文，不能称为数值等价优化。

## 完整对话：90 秒、两轮

输入为 4.16 秒真实 TTS 语音，以 16 kHz 单声道 PCM 实时发送；经过实际
ASR → LLM API → 本地 VoxCPM2 → DyStream/LIA → H264/AAC 管线。

| 测量项目 | 结果 |
|---|---:|
| 严格单卡检查（含计算、图形进程和 CUDA 工作线程） | 通过 |
| 显存峰值（整张目标卡，采样值） | 13318 MiB / 13.006 GiB |
| 解码视频帧数 | 1119 |
| 按真实采集时长计算的交付帧率 | 12.430 帧/秒 |
| 视频 PTS 时间轴帧率 | 12.497 FPS |
| 第一轮：语音结束到回复音视频边界事件 | 1915 ms |
| 第二轮：语音结束到回复音视频边界事件 | 1787 ms |
| 完整 fMP4 片段到达间隔 P95 / 最大 | 387 / 499 ms |
| 软件解码错误、采集错误 | 0 |

上表延迟是服务端回环网络测量，不含公网隧道、浏览器缓冲和声卡播放延迟。
到达间隔不是逐帧显示间隔；检查通过不等于保证任意公网链路不卡顿。
图像抽样检查可见发声口型、眨眼和头部变化，但尚未做感知质量或唇音同步评分。

原始报告：隔离部署的 `results/single_gpu_dialogue_final/report.json`，本地测量副本
保存在代码目录外的 `../measurements/dialogue_final.json`。原始视频留在隔离部署，
不纳入 Git，以免把参考人物素材和测试媒体直接发布。

回复的 started、media boundary、media ended 均对应同一个 `turn_id=1, generation=0`。

## CFG 数值验证与短时微基准

真实模型、同一语音与头像、相同随机种子。先预热 CUDA Graph，再重置随机种子；
每个条件生成 50 个动作帧，比较原 5 分支和裁掉零权重分支后的 4 分支。
不包含音频编码、渲染、TTS 或网络；单次短测试不能替代端到端持续吞吐测量。

| 条件 | 5 分支动作 FPS | 4 分支动作 FPS | 最大绝对差 |
|---|---:|---:|---:|
| Speaker | 106.873 | 118.180 | 8.8811e-6 |
| Listener | 107.100 | 118.588 | 2.5630e-6 |

两项均通过 `rtol=1e-4, atol=1e-4`；这次微基准增速约 10.6%–10.7%。
EMA 合并还通过真实 `torch_ema` CPU 权重逐元素相等回归。
原始数值：`../measurements/cfg_equivalence.json`。

## 验证中发现并修复的问题

1. MediaPipe 即使选择 CPU，仍会初始化 EGL，绕过 CUDA 可见卡限制在另一卡建立
   图形上下文。单卡模式现在同时选择 CPU delegate 并禁用该初始化阶段的 EGL vendor。
2. `nvidia-smi` 可能返回 TTS 工作线程 ID；基准工具现在核验其 Tgid 和启动标识，
   并检查完整 C/G 进程表，避免漏算 TTS 或图形占用。
3. 只在空闲期间压缩历史无法约束长回复；现在每个音频 hop 追加前检查长度上限，
   保留递归动作状态、未处理音频和不足整帧的采样余数。
4. 配置生成保留 Python 虚拟环境入口，不解析到系统 Python；清除旧部署版本门槛；
   复用 TTS 服务前验证实际进程的卡号和后端，防止误复用第二张卡上的旧服务。

早期未修全的 90 秒试跑达到 23730 MiB，并在另一卡残留 40 MiB，判定失败。
它和最终试跑的 LLM 回复长度不同，不作为严格的显存节省比例消融实验。

启动与复现命令见 [单卡部署说明](single_gpu_4090.md)。配置、权重及 API 密钥
保留在独立 runtime 目录，不纳入代码或测量报告。

本次相关回归共 59 个 Python 测试、5 组 Shell 检查通过；范围覆盖配置、EMA、CFG、
音频历史、头像预处理、基准归属、入口契约与 TTS 生命周期。这不是对整个仓库
所有功能、所有显卡或所有人物素材的全面质量认证。
